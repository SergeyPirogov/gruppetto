# Соціальне, етап 1: вхід, синхронізація профілю й лідерборди

Статус: готово до роботи · Автор: Serhii Pirohov · 2026-11-09

## Навіщо

Перші користувачі (переходять зі Zwift) кажуть одне: Gruppetto зручний для тренувань, але «немає мотивації» —
ти їдеш сам, і ніхто не бачить, що ти зробив. Друге питання — «двоє райдерів на одному компі» й «інший пристрій»:
зараз усе лежить у localStorage одного браузера.

Етап 1 дає перше спільне: **кожен підйом, спринт і коло — це таблиця з живими людьми**, а профіль (вага, FTP,
рівні, рекорди) живе в акаунті й однаковий на будь-якому пристрої.

Етапи 2 (живі групові заїзди) і 3 (клуби, стрічка, класифікації) — наприкінці, лише щоб етап 1 не закрив їм дорогу.

## Що входить

1. Вхід через Google (Supabase Auth). Необов’язковий: без входу все працює, як зараз, локально.
2. Синхронізація профілю між пристроями.
3. Результати на підйомах, спринтах і колах вбудованих маршрутів іде на сервер після заїзду.
4. Лідерборди: на екрані фінішу, на картці маршруту в лобі і в заїзді на панелі підйому.
5. Захист від неправдоподібних результатів на сервері.
6. Видалення акаунта й усіх даних однією кнопкою, сторінка конфіденційності.

## Що не входить (не робити)

- Живі заїзди з людьми, чат, друзі, клуби, стрічка, kudos — етапи 2–3.
- Лідерборди на GPX-маршрутах (у кожного свій файл; див. «Відкриті питання»).
- Синхронізація історії заїздів і секундних записів (IndexedDB) — їх і так зберігають Strava та intervals.icu.
- Синхронізація ключа intervals.icu й токенів Strava — **ніколи** не покидають браузер.
- Вибір жіночої моделі райдера (окреме завдання), магазин, валюта.

## Передумови (робить власник, не агент)

1. Проєкт у Supabase (Free). Регіон: Frankfurt (eu-central-1).
2. Google Cloud Console → OAuth client (Web). Authorized redirect URI — той, що показує Supabase
   (`https://<project>.supabase.co/auth/v1/callback`). Client ID і Secret вставити в Supabase → Auth → Providers → Google.
3. Supabase → Auth → URL Configuration: Site URL `https://automation-remarks.com/gruppetto/`, Redirect URLs додатково
   `http://localhost:8000/**` для розробки.
4. Передати агенту **Project URL** і **anon key** (вони публічні, лежатимуть у коді сторінки; захищає RLS).
   **Не** передавати service_role key.
5. Хост `<project>.supabase.co` має бути дозволений у мережі сесії агента — агент попросить сам.

Якщо передумов ще немає, агент робить усе на моках (див. «Тести») і залишає `js/social-config.js` з порожніми
значеннями — тоді соціальна частина просто не показується.

## Як влаштований застосунок зараз (важливо для агента)

- Без збірки: чисті ES-модулі в `js/`, сторонні бібліотеки лежать у `vendor/` (див. `vendor/three`). Supabase-js
  покласти так само: `vendor/supabase/supabase.esm.js` (ESM-бандл із jsdelivr, точна версія, з LICENSE). Не CDN у рантаймі.
- `sw.js` кешує `vendor/` «спершу збережене» — новий файл підхопиться сам.
- Налаштування: `settings` у `js/app.js`, ключ localStorage `powerup.settings`.
- Рекорди: `records` (`gruppetto.records`): `lap[routeId]`, `seg[climbId]`, `segTrace[climbId]`, `top[sprintId]`.
- Рівні: `progress` (`gruppetto-progress`), логіка в `js/progress.js` (`addRide`, `levelOf`, `BADGES`).
- Підйоми/спринти: id виду `${route.id}-c${k}` / `${route.id}-s${k}` (`js/routes.js`, ~рядки 221, 255) — шукаються
  автоматично з профілю висоти. Завершення сегмента — `updateSegments()` в `js/app.js`, туди ж пишеться `ride.efforts`.
- Коло/фініш: `records.lap` у `tick()`; `plausibleLap(t, length)` вже відсікає > 90 км/год.
- Симулятор: `ride.simulated === true`.
- Тексти: англійська — ключ, переклад у `js/i18n-uk.js`, `tr()`; статичний HTML перекладає `translateDom()`.
- Тести: `npm test` (`node --test tests/*.test.mjs`). Логіку тримати в чистих модулях, щоб тестувалась без браузера.

## Архітектура

```
js/social-config.js   SUPABASE_URL, SUPABASE_ANON_KEY ('' = соціальне вимкнене)
js/social-core.js     чисті функції: перевірки правдоподібності, злиття профілю, категорії, форматування таблиць
js/social.js          клієнт Supabase: вхід/вихід, sync профілю, відправка результатів, читання лідербордів, черга офлайн
supabase/migrations/0001_social.sql   таблиці, RLS, функції
privacy.html          конфіденційність (укр + англ)
```

`app.js` знає лише API `social.js`; без конфігу всі функції — no-op, і UI соціального не показується.

### Вхід

- `supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: <поточна сторінка без query> } })`.
- Повернення з OAuth не повинно зламати наявний розбір повернення Strava (`stravaReturn`, `?state=gruppetto-strava`).
  Supabase PKCE повертає `?code=` без нашого state — розрізняти за `state`.
- Кнопка входу: у картці профілю (поруч зі Strava/intervals.icu) і на екрані фінішу як заклик
  «Увійди, щоб твій час на {climb} потрапив у таблицю» (лише якщо в заїзді були сегменти).
- Після першого входу — коротке вікно: ім’я в таблицях (за замовчуванням `settings.name`), країна (прапорець, необов’язково),
  стать для фільтра (необов’язково: «чоловіча / жіноча / не вказувати»), галочка «показувати мене в таблицях» (увімк.).

### Синхронізація профілю

Синхронізується (білий список, а не весь `settings`):
`name, weight, height, ftp, wPrimeKj, maxHr, lthr, hrZones, hrZoneNames, jersey, stripe, bikeColor, lang`
+ `progress` + `records` (без `segTrace` — він великий; ghost-трек підйому лишається локальним).

Не синхронізується: пристрої, ключі/токени, графіка, звук, камера, вікна, усе, що про цей комп’ютер.

Правила злиття (`social-core.js`, з тестами):
- поля профілю — новіше за `updated_at` перемагає (поле `settingsUpdatedAt` вести локально при кожній зміні з білого списку);
- `records.lap/seg` — мінімум часу за ключем, `records.top` — максимум;
- `progress` — той, у кого більше `xp`; бейджі — об’єднання з найранішою датою.

Коли: при вході, при відкритті сторінки (якщо увійшов), після кожного заїзду, після зміни профілю (debounce 3 с).
Перший вхід на пристрої з локальними даними — злити, не перезаписувати.

### Що йде в лідерборд

Після заїзду, якщо увійшов і **не** симулятор:
- кожен завершений підйом і спринт з `ride.efforts` вбудованого маршруту;
- коло (або фініш для `oneWay`) вбудованого маршруту з `ride.lapTimes`.

Для кожного результату потрібні середня потужність і пульс за відрізок — зараз у `efforts` є лише час.
Додати в `updateSegments()` (і для кола в `tick()`): середня потужність і пульс від `S.t0` до кінця з `recorder.samples`.

Поля: `segment_id`, `kind` (`climb|sprint|lap`), `route_id`, `route_version`, `time_s` (0.1 с), `avg_power`,
`avg_hr`, `weight_kg`, `ftp`, `top_speed_kmh` (спринти), `ridden_at`, `client` (версія застосунку).

`route_version` — короткий хеш профілю висоти маршруту (довжина + висоти через кожні 100 м), щоб зміна вбудованого
маршруту в коді не змішала старі й нові часи. Обчислити в `social-core.js`, той самий для всіх клієнтів.

Офлайн: невідправлене — у черзі в localStorage (`gruppetto.social.queue`), відправити при наступному відкритті.

### Правдоподібність (і на клієнті, і в SQL-функції — сервер головний)

Відкидати (не зберігати), якщо:
- `weight_kg` поза 30–200, `ftp` поза 50–600;
- швидкість > 25 м/с середня (як `plausibleLap`) або `time_s` < 5;
- середні Вт/кг за відрізок вищі за стелю за тривалістю (≈ світовий рівень + запас):
  ≤ 1 хв: 13 · ≤ 5 хв: 8 · ≤ 20 хв: 6.8 · довше: 6.3 Вт/кг;
- `avg_power` = 0 (немає даних потужності);
- більше 200 відправок від одного користувача за добу.

Позначати, але показувати (колонка `flags`): немає пульсу; Вт/кг вище за 90 % стелі. У таблиці — тихий значок «?».

Неперевірне (вага, калібрування тренажера) — чесно визнаємо; це як у Zwift. Місце для майбутнього — скарга на результат.

### Лідерборди

Для кожного сегмента і кола:
- **Фільтри:** Усі час / Цей місяць / Цей тиждень · Усі / Жінки / Чоловіки · Категорія A/B/C/D.
- **Категорія** — за FTP/вага в момент заїзду: A ≥ 4.0, B 3.2–4.0, C 2.5–3.2, D < 2.5 Вт/кг.
- Один рядок на людину (її найкращий час у фільтрі).
- Показати топ-10 і «вікно» навколо мене (±3), якщо я нижче.
- Рядок: місце, прапорець, ім’я, час, Вт/кг, середній пульс, дата.

Де видно:
1. **Екран фінішу:** у блоці сегментів біля кожного часу — «#14 з 213 · тиждень #3». Клік — повна таблиця (шухляда).
2. **Лобі, картка маршруту / сторінка підйому:** лідер, мій найкращий і моє місце; кнопка «Таблиця».
3. **У заїзді, панель підйому (`seg-panel`):** поруч із рекордом — час лідера тижня у моїй категорії.
   Опційно: «привид» лідера тижня (його `segTrace` не зберігаємо — лише рівний темп від його часу, як зараз без треку).

Читати таблиці можна і без входу (публічні). Відправляти — лише увійшовши.

## Схема бази (Supabase / Postgres)

```sql
create table profiles (
  id uuid primary key references auth.users on delete cascade,
  display_name text not null check (char_length(display_name) between 1 and 24),
  country char(2),
  gender text check (gender in ('m','f')),          -- null = не вказано
  public boolean not null default true,              -- показувати в таблицях
  data jsonb not null default '{}',                  -- білий список налаштувань + progress + records
  updated_at timestamptz not null default now(),
  created_at timestamptz not null default now()
);

create table efforts (
  id bigint generated always as identity primary key,
  user_id uuid not null references profiles on delete cascade,
  segment_id text not null,                          -- 'carpathians-c2' / 'rolling-lap'
  kind text not null check (kind in ('climb','sprint','lap')),
  route_id text not null,
  route_version text not null,
  time_s numeric(8,1) not null,
  avg_power smallint not null,
  avg_hr smallint,
  weight_kg numeric(5,1) not null,
  ftp smallint not null,
  wkg numeric(4,2) generated always as (avg_power / weight_kg) stored,
  category char(1) not null,                         -- A/B/C/D, рахує функція
  top_speed_kmh numeric(5,1),
  flags text[] not null default '{}',
  ridden_at timestamptz not null,
  created_at timestamptz not null default now(),
  client text
);
create index on efforts (segment_id, route_version, time_s);
create index on efforts (user_id, created_at);
```

RLS:
- `profiles`: читати публічні поля (`display_name, country, gender`) — усім для `public = true`; `data` — лише власник
  (окремий view `public_profiles` без `data`, або колонкові гранти); писати — лише власник.
- `efforts`: читати — усім, якщо профіль `public`; **прямого insert немає** — тільки через функцію.
- Функції `security definer` з явним `search_path`:
  - `submit_efforts(items jsonb)` — перевірки правдоподібності, ліміт на добу, рахує `category` і `flags`, вставляє.
    Повертає для кожного: збережено/відхилено (причина) і місце.
  - `leaderboard(segment text, version text, period text, gender text, category text, around_me boolean)` —
    найкращий на людину, топ-10 + вікно навколо `auth.uid()`.
  - `delete_me()` — видаляє `auth.users` запис (каскадом усе).

Міграція — у `supabase/migrations/0001_social.sql`, придатна для `supabase db push` і для вставки в SQL Editor.

## Конфіденційність

`privacy.html` (укр/англ), посилання з картки входу й футера:
що зберігаємо (ім’я в таблицях, країна, стать — якщо вказано, вага, FTP, пульсові межі, рекорди, результати сегментів),
навіщо, де (Supabase, ЄС), хто бачить (публічно — ім’я, країна, результати й Вт/кг; вагу окремо не показуємо),

Ніяких трекерів у соціальному коді; `track()` (GoatCounter) — лише анонімні події, як зараз (`social-login`, `social-submit`).

## Етапи 2–3 (не робити, лише не заважати)

- **Етап 2 — живі групові заїзди.** Supabase Realtime (broadcast-канал на заїзд): позиція, потужність, швидкість,
  смуга раз на секунду; розклад заїздів (`events`), лобі «скоро старт», боти добивають групу. Драфтинг і пачка
  (`js/bunch.js`) працюють з людьми так само, як з ботами — тримати `riders[]` однаковим за формою.
- **Етап 3 — клуби й стрічка.** `clubs`, `club_members`, стрічка заїздів друзів, «респект», форма клубу
  (Team Ukraine), гонки з класифікаціями (зелена/горохова) поверх результатів сегментів з етапу 1.

## Відкриті питання (вирішить власник, агент обирає замовчування в дужках)

1. Лідерборди на GPX-маршрутах — за хешем треку, щоб друзі з тим самим файлом бачили одне одного? (ні, етап 3)
2. Показувати Вт/кг у публічній таблиці? (так — це те, що всім цікаво; вагу окремо — ні)
3. Країна за замовчуванням з мови браузера? (ні, лише якщо вказав сам)
4. Вхід ще й через Strava чи пошту? (лише Google на етапі 1)
